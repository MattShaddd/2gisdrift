# Обновления

## Магазины — основной путь

Подать ZIP из Releases в Chrome Web Store и Microsoft Edge Add-ons, объяснив необходимость `debugger`: текущая логика столкновений запускается внутри worker-потоков карты. Добавить политику приватности и материалы для карточки. Браузер обновляет опубликованные версии с увеличенным номером. Выпуск GitHub Release не публикует обновление магазина автоматически; учётная запись издателя и проверка магазина остаются внешними шагами.

Официальные источники:
- https://developer.chrome.com/docs/extensions/how-to/distribute
- https://developer.chrome.com/docs/extensions/develop/migrate/remote-hosted-code
- https://developer.chrome.com/docs/extensions/reference/api/debugger
- https://learn.microsoft.com/en-us/microsoft-edge/extensions/publish/hosting-and-updating

## GitHub Releases / dev

`scripts/update-dev.ps1` использует только заранее настроенный GitHub origin и явно указанный тег, отказывается работать с изменёнными отслеживаемыми файлами, делает fast-forward, собирает пакет и проверяет его. Git не перезаписывает существующие теги при fetch. Перед обновлением просмотрите release и изменения автора. Скрипт не запускается расширением или планировщиком и не загружает исполняемый код на страницу через сеть. Доверие к автору/аккаунту GitHub необходимо: SHA-256 рядом с ZIP проверяет целостность, но не является независимой подписью автора. Для более строгой доставки используйте подписанные теги с заранее проверенным ключом.

Unpacked расширения Chrome не имеют штатного канала автообновления; после обновления папки пользователь нажимает Reload. Автоматическую загрузку и исполнение JS из ветки GitHub не используем: MV3 требует упакованный код, а движущаяся ветка увеличивает риск поставки нежелательных изменений.

## Self-hosted CRX

На управляемых устройствах можно подписывать CRX3 одним сохранённым приватным ключом, размещать CRX и XML update manifest по HTTPS и настроить enterprise policy. В manifest потребуется `update_url`, в XML — стабильный extension ID, URL CRX и возрастающая версия. На обычном Chrome под Windows/macOS установка self-hosted расширений ограничена политиками предприятия; Edge тоже имеет ограничения для таких устройств. Поэтому фиктивный `update_url` в dev-пакет не добавлен. Приватный ключ подписи не хранится в Git. Пока нет домена, ключа и управляемого окружения, этот путь документирован, но не объявлен работающим каналом.
